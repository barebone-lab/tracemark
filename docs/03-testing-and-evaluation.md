## 9. 測試與評估

### 9.1 目前已測範圍

2026-11-21，在 Python 3.12.13 的本機環境執行：

```bash
env -u RUN_DEEPSEEK -u WATERMARK_LLM uv run --locked pytest -q tests
```

結果：**82 passed, 2 skipped，129.37 秒**。

兩個 skipped 分別是：

1. 需要外部 DeepSeek API 的 `text_lexical` 測試（未設定 `RUN_DEEPSEEK`）。
2. 需要真實 MLX 模型的 `text_generative` 測試（未設定 `WATERMARK_LLM`）。

生成模式的測試使用 fake model，驗證 API、載荷流程與統計判斷。當時的 `text_lexical` 實驗曾以兩款字體渲染同一份英文樣本，經 Tesseract OCR 後成功提取水印。這項實驗已從目前的測試套件移除。

### 9.3 評估指標

| 指標 | 定義 | 方向 | 用途 |
|---|---|---|---|
| PSNR | `10 log10(MAX² / MSE)` | 越高越好 | 圖像失真；目標 ≥ 40 dB |
| SSIM | 結構相似度（Wang et al., 2004） | 越高越好 | 圖像感知品質；目標 ≥ 0.98 |
| BER | 錯誤位元／總位元 | 越低越好 | 穩健模式；目標 ≤ 5% |
| NC | 正規化相關 | 越接近 1 越好 | 與原始載荷的相似度 |
| Top-1 | 正確候選排第一的比例 | 越高越好 | `identify`；目標 ≥ 90% |
| FPR | null keys 被誤判為有效的比例 | 越低越好 | 目標 < 1% |
| Coverage | 測試覆蓋率 | 越高越好 | 目標 ≥ 80% |

`ExtractResult.score` 不是上述指標的統一換算，也不是「屬於某人的機率」。它是模式內部的品質／證據指標：`image_fragile`／`text_invisible` 成功為 1；`text_lexical` 反映糾錯餘量；`image_robust` 反映解碼一致度；key-only／生成模式用統計證據。文件與簡報不得把 `score` 寫成準確率或定罪機率。

### 9.4 實驗設計

目前已做的：

- **圖像**：以合成圖為主，加入 JPEG、縮放、模糊、雜訊、調色、旋轉、裁切、模擬截圖與模擬翻拍，並量測 PSNR／SSIM、null 試驗與 `identify`（見 9.7）。測試目的是找出失敗邊界，不是產生漂亮的平均數。
- **文字**：以團隊自行撰寫的英文段落與兩款字體的圖片樣本為主；`text_lexical` 的 7,000／3,000／2,000 words 樣本用於容量與 key-only 的行為，不是通用容量保證。
- **候選密鑰**：`identify` 測試使用多個候選，檢查 `match`／`none`／`ambiguous` 與 `results` 的順序。
- **環境**：Python 3.12.13、`uv run --locked`；外部 API 與真實 MLX 模型在預設測試中跳過，避免把網絡或模型下載當成測試前提。

尚未做的：

- 30 張 CC0 真實圖像、10 份文件掃描、20 份中文 + 10 份英文文本的統計實驗；這是原規劃，尚未執行（9.7 只用 5 張合成圖）。
- 1 個正確密鑰 + 9 個干擾密鑰、重複 100 次的 top-1 量測（9.7 只做了 4 次、每次 20 個候選）。
- 真實外洩樣本或用戶研究；目前沒有這類資料，因此不宣稱真實場域的成功率。
- 手機翻拍與列印—掃描的大規模測試；目前只有模擬案例。

### 9.6 效度限制

- **合成圖偏誤**：合成圖的紋理與真實筆記頁面不同；9.7 已顯示白底文件頁明顯較難，真實掃描、手機翻拍、補習社排版可能更難。
- **OCR 樣本偏誤**：兩款字體與 Tesseract 的結果不能推廣到所有字體、語言與解析度。
- **小樣本**：容量樣本只有特定英文段落，不能當作通用容量公式。
- **無真實外洩資料**：沒有真實買家、真實轉售或真實法律案例；所有「追溯」描述都是設計目標與技術能力，不是已證實的場域成效。
- **未量測 coverage**：因此不能說「測試覆蓋率達 80%」。
- **外部依賴**：DeepSeek API 與 MLX 模型在預設測試中跳過；它們的行為可能隨版本、網絡與模型變化。

這些限制應與結果一併閱讀，而不是放在附錄後被忽略。

### 9.7 圖像實驗結果（2026-11-21）

以 `tracemark` 0.1.1（commit `72f8a9a`）在 MacBook Pro（Apple silicon，CPU）執行，總耗時 2,095 秒。腳本只使用程式生成的圖，因此可重現；腳本、完整 log 與逐項 JSON 放在本機 `tmp/image_watermark/`（`tmp/` 不納入 git）。

**測試圖片**：3 張合成相片紋理（720×1000、900×1600、600×600）、1 張講義投影片（720×1280）、1 張白底黑字文件頁（1100×850）。

**版面**：`hidden_id`（隱形磚塊，藏 `b"ID7"`，strength 1.0）、`markers`（8 個 ArUco 標記，marker_strength 0.4）、`key_only`（payload `b""`，strength 0.5）。

**表 9：畫質（原圖 vs 標記圖，PSNR dB／SSIM）**

| 圖片 | hidden_id | markers | key_only | fragile |
|---|---|---|---|---|
| 紋理 720×1000 | 40.5／0.973 | 25.9／0.952 | 46.2／0.992 | 90.9／1.000 |
| 紋理 900×1600 | 40.6／0.980 | 26.8／0.966 | 46.1／0.994 | 93.8／1.000 |
| 紋理 600×600 | 40.6／0.966 | 24.6／0.927 | 46.1／0.990 | 88.3／1.000 |
| 投影片 720×1280 | 39.7／0.973 | 25.9／0.947 | 45.1／0.992 | 92.5／1.000 |
| 文件頁 1100×850 | 36.2／0.975 | 23.9／0.942 | 41.2／0.991 | 92.8／1.000 |

markers 的 PSNR 較低，主要因為標記本身是可見方塊；這個版面以可見度換取翻拍時的穩健度。嵌入時間每張 0.02–0.11 秒。

**表 10：17 種攻擊下以正確密鑰提取（成功數／17）**

攻擊：無、JPEG 70／50／30、縮放 0.5×／0.35×、模糊 σ2／σ3、雜訊 σ8、調色、截圖 + JPEG 60、右裁 10%、底裁 20%、兩邊各裁 10%、旋轉 7°、模擬翻拍、較難的模擬翻拍。

| 圖片 | hidden_id | markers | key_only |
|---|---|---|---|
| 紋理 720×1000 | 17 | 17 | 17 |
| 紋理 900×1600 | 17 | 17 | 17 |
| 紋理 600×600 | 17 | 17 | 17 |
| 投影片 720×1280 | 17 | 17 | 17 |
| 文件頁 1100×850 | 15 | 16 | 11 |
| **合計** | **83／85** | **84／85** | **79／85** |

所有失敗都在文件頁：hidden_id 失敗於兩種翻拍；markers 失敗於兩邊裁切（標記被裁去一半）；key_only 失敗於 JPEG 50／30、模糊 σ3、雜訊、兩種翻拍。程式會按局部紋理降低平坦區的強度以避免白底出現斑點，因此白紙上可藏的訊號很少。key_only 此處只用 strength 0.5，與 hidden_id 的 1.0 不是同強度比較。保護講義或筆記頁時，應改用 markers 版面或提高 strength。

提取時間中位數（最慢）：markers 0.1 s（4.7 s）、hidden_id 0.5 s（10.3 s）、key_only 3.0 s（14.2 s）。

**fragile 模式**：原檔與重新存 PNG 5／5 成功；JPEG 95、0.5× 縮放、裁切 10% 均 0／5，符合設計。

**誤認（null 試驗）**：120 張未以測試密鑰標記的圖（40 張無水印、40 張以其他密鑰做 key-only、40 張以其他密鑰藏 ID；450–1300 px；再經原圖、JPEG 50、截圖、旋轉 5°、翻拍或 0.5× 縮放之一），**0 次誤認**。key-only 最高峰值 z 平均 5.47、最高 6.53，低於 3×10⁻⁵ 誤認率對應的門檻 8.87；與早期 600 張校準（平均 5.42、最高 6.75）一致。

**`identify`（20 個候選密鑰）**：JPEG 60 與模擬翻拍兩種洩漏副本 × hidden_id／key_only，4 次全部找到正確候選。耗時：JPEG 副本約 50 秒，翻拍副本 251–274 秒（約每個密鑰 12 秒）。現場示範應只用少量候選（3–5 個），候選多時的速度是待改進項目。

**早期實驗（2026-11-16 至 18，原始數據已遺失，結論見 `tracemark/image_robust.py` 開頭說明）**：225 張模擬手機相中，markers 版面由舊版 107 張提升到 187 張（marker_strength 0.4）；不同 strength 下 key-only 比藏 ID 更耐壓縮與模糊（strength 0.2 時 10／15 vs 6／15）。
